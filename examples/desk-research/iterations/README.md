# 三轮质量迭代：从结果到 Trace

这个示例用同一组早餐研究题，展示怎样逐步改进 Agent：先建立具备完整研究能力的 Baseline，再根据最终结果改善表达与推断，最后沿 Trace 改善取证和引用过程。

| 轮次 | 为什么做 | 怎么做 | 本次观察到的收益与局限 |
| --- | --- | --- | --- |
| [Baseline](00-baseline/README.md) | 建立可比较的起点 | 搜索、读取正文，用 DO 保存和读取研究简报 | 四题自动通过 2/4；预算和反例题的推断失分，暴露了结论越过证据的问题 |
| [第一次迭代：专注结果](01-result-focused/README.md) | 回答有来源，仍可能错配事实或夸大适用范围 | 逐条对照最终回答和 Judge 理由；只改指令，要求关键事实对来源、限定结论主语与样本范围 | 四题自动通过 3/4；两项 inference 从 0 变 1，但早餐范围题 evidence 从 1 变 0，说明改动也有退化 |
| [第二次迭代：专注 Trace](02-trace-focused/README.md) | 结果要求不能保证实际读到正文、正确传递引用 | 检查搜索、读页、保存和最终交付；收敛证据集，使用来源标识和工具生成的链接，再针对预算题检查反例和读取过程 | 首批四题自动通过 4/4，早餐范围题 evidence 恢复为 1；人工仍发现预算反例遗漏，后续单题记录单独保留 |

## 1. 建题

[8 元预算题](../BENCHMARKS.md#1-建题从业务风险到-casejson)展示如何把业务风险写成输入、验收条件和 Judge。三轮使用相同的四道单轮题（早餐范围、预算上限、反证、验证计划）及同一道多轮澄清题，保持题目、Judge、模型和预算一致。

## 2. 跑分

按[运行与复现说明](REPRODUCING.md)选择对应源码，再执行[默认四题命令](../README.md#2-跑分)和 `clarify-breakfast`。分别保存执行结果和评分；执行错误、Judge 错误、有效 0 分各自记录。

## 3. 定位失分

第一次先读回答：哪句超出了证据，Judge 为什么扣分？第二次再读 Trace：搜了什么、读了哪些正文、引用从哪里来、保存后是否改写？[预算题示例](../evaluation/README.md#本次例子从预算题原句走到工具证据)说明：即使读到了正文且自动评分通过，仍可能遗漏同页反例。

## 4. 改 Agent

第一次迭代只收紧结果要求，不改变搜索、存储或正文工具。第二次保留这些要求，再改研究过程和引用工具：用较小证据集逐一核对正文，通过来源标识生成链接，减少手写链接错配。各轮 README 提供可直接交给 coding agent 的任务文本。

两次迭代的价值分别是让结论边界更明确、让证据传递更可核对。它们需要同时结合自动评分与人工证据检查，不能仅用总分证明质量。

## 5. 再跑分

| 轮次 | 单轮自动通过 / 4 | 单轮质量失分 | 澄清题 conversation / coverage | 判分完成 | 人工争议 |
| --- | ---: | ---: | --- | ---: | ---: |
| Baseline | 2 | 2 | 1 / 1 | 14/14 | 1 |
| 专注结果 | 3 | 1 | 1 / 1 | 14/14 | 1 |
| 专注 Trace | 4 | 0 | 1 / 1 | 14/14 | 1 |

这是同一候选工具链下、预算题后续修正前的首次批次。[逐项对照](comparison.md)保留了改善、退化和人工争议；[机器汇总](run-summary.json)保留执行与判分状态。发布版首次执行的 12 个错误和评分中断也完整保留，不与此表混算。

预算题的三次后续尝试分别为评分不完整、自动通过但仍有错链、自动通过且成功读取三次正文；[详细记录](02-trace-focused/README.md#预算题后续尝试)保留全部回答、错误和残余争议，不替换首批四题分数。其余 8 道单轮和 5 道多轮题未纳入比较；这些结果不代表完整题集、正式发布工具链或业务验收通过。
