# 03：让结论范围与证据范围一致

## 为什么还需要一轮

02 的 `breakfast-scope` 已完成的简报把 2019 年的新闻个案和 2018 年的个人帖子，合成为“到岗后吃早餐在不少公司已是常态，核心矛盾在气味和时长管理，不在能否吃”。原文能证明这些情形出现过，不能证明发生率或顾虑排序。

这与 00 的 inference Judge 指出的“把有限样本升级为核心顾虑”是同一类缺陷。链接正确、报告更短，都不能自动解决推断过度。

## 单一假设与改动

增加收尾时的主语检查：个案写该报道中的人，调查写受访样本；没有代表性比较证据，不用“常态、普遍、核心痛点、市场空白”等词概括总体。同时要求机会假设写明验证对象、动作、观察和否定条件，让假设可以被推翻。

本轮仍只改 instructions，同步无 DO 阶段文件。没有给 Agent 预设市场结论，没有替换 Exa、模型、工具或评分标准。

## 检查重点

检查相同四题是否在关键句本身保留样本限制，而不是仅在末尾贴免责声明；检查是否仍能给出实际方案与可执行研究计划。只说“证据不足”并不是通过标准。

最终结果和回归单独记录；不能将修复了开发集的一个措辞问题，直接推广为所有 18 题均通过。
