# R4 交接问题归类

2026-11-17 用户要求把已停止 R4 的仍有效问题归入“看结果 / 看 Trace”。依据是当日 `HANDOFF-TO-3ROUNDS.md` 及其未推补丁（SHA-256 `ab6f688f1091164c15e1e9823d88b4e2538603f9927000d35a1fd18769cfb00a`）。R4 是不同源码、SDK、运行器和输出预算配置下的历史证据；它的分数不进入新三轮对照，也不代表本次复现了同一缺陷。

## 第一次迭代：结果视角

| 仍需核对的问题 | 历史证据 | 本轮怎么使用 |
| --- | --- | --- |
| 个案被写成人群主流预算 | R4 的旧 01 / budget-ceiling 将一个受访者的 10 元习惯写成“主流心理预算高于8元”，原 inference=0 | 归入结论主语与样本范围检查；第 1 轮的 instructions 限定个案、调查样本，禁止无代表性总体结论。新运行若没有成稿，记不可评，不能宣称修复 |
| 购买行为被推成偏好或决策权重 | R4 conflicting-findings 人工发现“购买行为→便捷/低价主导偏好”；后续重评与原自动分数不同 | 归入事实到结论的推断跨度；复核回答原句是否有同群体明确表达或同样本直接测量。免责声明不能抵消前面的强断言 |
| 验证计划改变用户限制 | 无热水的试验又引入自备热水 / 保温杯 | 归入结果的条件保留与假设验证。检查实验、对照和放弃条件是否仍符合用户原限制；不能只检查推荐列表 |
| 机会问题的前提与事实矛盾 | R4 最后 no-microwave 机会问句写“需到店即食的热食”，案例却是带到工位吃 | 作为尚待人工复核的前提矛盾，不因某项 Judge=1 自动关闭。检查发现、假设、实验中的对象和场景是否一致 |

这些问题归入第 1 轮的任务与复核清单，不给第 2 轮添加新的 subject / fit / constraint 推断规则。新三轮实际执行失败时，没有回答原句就明确记为无法验证，而不是移用 R4 的答案或分数。

## 评测和运行条件：不计为两轮 Agent 提升

- [opengea #41](https://github.com/bmrlab/opengea/pull/41) 的正文证据门槛与多轮分页规则已经在本次固定 main `4f4f51c` 中，三轮共同使用。
- R4 报告 [gea #1393](https://github.com/bmrlab/gea/pull/1393) 已合并，修复 Judge 不存在 messageId 后正确补读的闭环。本次发布版 CLI/SDK 不因此自动具有该候选 SDK 的修复；记录实际版本，不把 R4 校准通过冒充本次验收。
- CR `max_tokens` 后未关闭工具参数块、`end_turn` 与内容不匹配、chunk timeout 属于协议/执行故障。R4 有结构事件支持前两类；本次只有对应事件才可同样归因，不从通用 error 猜根因。
- R4 显式总输出 4096、思考 1024 的 Catalog 是运行条件变化，不是 Agent 提升。发布版首次批次使用内置 CR 配置且全部执行失败、评分未完成。收到交接后，三轮整批统一使用该显式 Catalog 与候选运行器，另存全部新结果；两批不混用，没有采用关闭思考或放宽严格协议校验。
- 原零来源问题在 R4 已解除，本次也有多题取得真实 Exa 来源；不能继续把所有失败归因于缺 key。短暂搜索失败与后续模型等待分别核对。
- R4 的更短结构化 observations / hypotheses、结构化 gaps 和加强 inference Judge 的未推补丁未整包套用。尤其不能只给某一轮换 Judge；本任务仍使用同一 main Judge。

R4 的各批原始失败、评分不完整、人工争议及离线回放各有独立意义。这里保留问题分类与核对方法；[新三轮结果](comparison.md)只来自本任务同条件真实运行。
