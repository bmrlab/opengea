# Ask Muse

An Agent that answers questions using the user's [MuseDAM](https://musedam.cc/) assets. It connects directly to [MuseDAM MCP](https://mcp-service.musedam.cc) through user OAuth. There is no application UI and no custom Tool wrapper: GEA discovers and exposes the MCP server's Tools to the Agent.

## Files

- `agent.ts`: Agent capabilities, disabled Computer and public OAuth client ID requirement.
- `AGENTS.md`: search, evidence, citation and authorization instructions.
- `connectors/musedam.ts`: Streamable HTTP MCP, OAuth and `connection: { principalType: "user" }`.
- `agent-*.json` and `scripts/run-agent.mjs`: reproducible CLI inputs and local environment loading.

The Connector uses `require({ scopes: ["musedam"], exposeToModel: true })`. It does not declare an operation list or reimplement the server's input/output schemas. Live MCP discovery supplies the available tools after authorization.

## Install and validate

Use Node **24.16.0**, pnpm **10.30.3**, and SDK/CLI **0.1.260908-alpha.0**. From this directory:

```bash
pnpm install --frozen-lockfile
pnpm type-check
npm install --global @gea-ai/cli@0.1.260908-alpha.0
pnpm agent:validate
pnpm agent:pack
```

Installation and type checking need no credentials or private GEA checkout. The CLI currently supports macOS ARM64 and Windows x64; Linux type checking does not need the CLI.

## OAuth configuration

The public client ID for this example is `muse-mcp`. It is configuration, not a secret. No client secret is needed. MuseDAM advertises Authorization Code with S256 PKCE and the `musedam` scope in its [authorization metadata](https://musedam-service.tezign.com/.well-known/oauth-authorization-server) and [protected resource metadata](https://mcp-service.musedam.cc/.well-known/oauth-protected-resource).

The callback must be allowed by the MuseDAM OAuth client:

| Execution                 | Callback                                                  |
| ------------------------- | --------------------------------------------------------- |
| Local `gea agent connect` | `http://127.0.0.1:8788/oauth/callback`                    |
| Hosted GEA                | `https://musegea.com/api/agent-connectors/oauth/callback` |

For another GEA installation, replace the hosted origin with that installation's application URL and register its callback with MuseDAM.

## Run locally

Copy `.env.example` to `.env`. Keep `MUSEDAM_MCP_CLIENT_ID=muse-mcp` and fill in your `CREATIVE_REASONING_API_KEY` for local model calls. Then authorize your own MuseDAM account:

```bash
pnpm connect
pnpm dev
```

`pnpm connect` opens the MuseDAM login/authorization page and waits for the loopback callback. Credentials stay in the CLI's local credential store, scoped to this project; they are never uploaded with the Agent. The local development default principal is `local-user` and is intended for the developer's own account.

The Agent listens on `127.0.0.1:8789`. In another terminal:

```bash
curl --no-buffer http://127.0.0.1:8789/gea/agents/ask-muse/run \
  -H 'content-type: application/json' \
  --data '{"message":"搜索与品牌相关的素材，挑选三个结果，说明用途并引用素材链接或 ID。","chatId":"ask-muse-demo"}'
```

This returns AI SDK event-stream data. Reuse `chatId` for a follow-up and change it for a new conversation. No UI, local GEA login or Project API key is required. The local launcher reads `.env`; it does not fetch hosted environment variables. Agent validation and packing do not require model or OAuth credentials.

If you prefer hosted models with the local Agent, sign in with `gea login`, select your Workspace, export `MUSEDAM_MCP_CLIENT_ID=muse-mcp`, and run:

```bash
gea agent dev --json '{"cwd":".","host":"127.0.0.1","port":8789,"modelSource":"hosted"}'
```

## Publish and use in GEA

Create a Studio Project in your intended organization/Workspace, sign in through the CLI, and select that Workspace. Replace `my-project` with the Project's current slug:

```bash
gea agent push --json '{"cwd":".","project":"my-project","slug":"ask-muse"}'
```

In the Project or Agent environment settings, configure the non-secret variable **`MUSEDAM_MCP_CLIENT_ID=muse-mcp` for Preview**. Open the Agent's Preview Playground and ask a question. The Agent returns a connection link when it needs authorization. Open that link, authorize MuseDAM, then send the question again. Local credentials are not promoted to Studio.

Each signed-in GEA user gets their own Studio identity, `gea:<userId>`, generated by GEA. OAuth authorization is bound to that identity and the selected Project/environment. The Agent does not inherit existing GEA personal Connector credentials. Preview and Production Connections are separate; configure and authorize the intended environment.

An external application can also invoke the Agent through the server-side `StudioAgentClient`, using a Project API key and its own stable user principal:

```ts
await client.run({
  message: "Find brand assets and explain which ones are relevant.",
  principal: { principalType: "user", principalId: "customer-123" },
});
```

The application's backend owns user authentication and principal selection. Do not send a `gea:` principal; that namespace is reserved for GEA. Hosted API calls that omit a user principal cannot authorize user-owned Connections. Opening an authorization link does not automatically resume the completed request: retry or continue the conversation afterward.
